# 国际化维护

项目统一使用 Vue I18n 11 的 Composition API。应用入口安装共享的 `i18n`，独立注册表组件通过同一个 Composer 工作，不强制消费应用安装插件。英文为回退语言；`bui-locale` 保存选择，首次访问匹配浏览器语言。

## 文案资源与入口

- `src/lib/locales/en.ts`：英文资源，以及由结构推导的 `MessageSchema`、`MessageKey`。
- `src/lib/locales/zh-CN.ts`：中文资源，按 `MessageSchema` 检查键是否齐全。
- `src/lib/i18n.ts`：Vue I18n 实例、`locale`、`setLocale` 与类型约束的 `t`。

所有界面文案直接引用稳定键。修改英文只改资源值，无需改变调用位置。新增键同时加入两份资源；漏键和引用不存在的键会导致类型检查失败。

```tsx
import { t } from '@/lib/i18n'

// en: "Show diff for {file}"；zh-CN: "查看{file}的差异"
return () => <button aria-label={t('toolChips.showDiff', { file: file.value })} />
```

新句式优先使用命名参数，已有句式可用 Vue I18n 的列表插值。参数都是原始数据，不隐式翻译。默认文案在 render、模板、computed、工厂函数或对象 getter 中调用 `t`；禁止在模块初始化时缓存翻译后的字符串或 VNode。路由使用 `titleKey`，注册表元信息保留 getter，避免复制对象时固定语言。

含 `@`、`|` 等保留字符的资源使用字面量插值，例如 `{'@'}`。复数规则、日期和数字格式化可通过 `i18n.global.t/d/n` 使用，按业务需要配置格式；保留结构化日期和数值，不以英文格式化结果作为翻译键。

## 文案与业务数据

默认示例文案在定义处调用 `t`。组件的外部标签、代码、命令、文件名、路径、用户消息和其他业务字符串直接显示，由调用方按需求翻译。不存在英文原文查词表、递归翻译参数或兼容翻译入口。

类型、列、标签、变体等业务标识保持稳定，单独关联明确的展示键。默认示例的本地化不改变这些标识；外部表格行和标签不参与示例翻译。语言切换保留编辑内容与选中状态；真实流式内容更新启动新的完成周期，默认示例切换语言保持当前进度和完成状态。

## 增加语言

1. 新建 `src/lib/locales/<locale>.ts`，导出满足 `MessageSchema` 的资源。
2. 在 `src/lib/i18n.ts` 导入并加入 `messages`，语言类型与存储校验自动推导。
3. 在 `LanguageToggle.tsx` 增加选项与辅助说明。
4. 按语言检查流式分词及间距；当前中文示例按字符显示，英文按空格显示。
5. 使用系统 pnpm 执行 `pnpm typecheck`、`pnpm test`、`pnpm build`，检查排版、搜索、状态保留和独立组件。

构建会把 Vue I18n 与语言资源纳入注册表依赖闭包。需要 `useI18n`、`i18n-t` 或模板注入的消费应用应安装导出的 `i18n`。当前实例按客户端模块共享；多个 Vue 应用需要互相独立的语言状态时，需为它们创建独立实例。
